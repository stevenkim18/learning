01

LCEL이란 무엇일까?

LCEL은 LangChain Expression Language의 약자야.

쉽게 말하면 여러 처리 단계를 연결해 하나의 실행 흐름을 만드는 표현 방식이야.

예를 들어 AI를 이용해 문장을 요약하는 프로그램을 만든다고 생각해 보자.

LCEL의 기본 실행 흐름

입력값

{"topic": "Python 함수"}

① ChatPromptTemplate

프롬프트 변수 치환

② ChatOpenAI

실제 LLM 호출 및 답변 생성

③ StrOutputParser

응답에서 텍스트 추출

최종 결과

Python 문자열(str)

각 단계의 출력이 다음 단계의 입력으로 전달돼.

LCEL의 중요한 장점은 처리 단계를 재사용하고 조합하기 편하다는 거야.

LangChain 공식 API에서는 이러한 연결을 RunnableSequence라고 부르며, | 연산자 또는 pipe()로 만들 수 있어. 공식 문서 ↗공식 문서 ↗

02

Runnable이란?

2-1. Runnable을 한 문장으로 이해하기

Runnable은 입력을 받아 어떤 작업을 수행하고 결과를 반환하는 공통 실행 인터페이스야.

Python 함수를 생각하면 이해하기 쉬워.

Python
def double(number):    return number * 2

이 함수는 숫자를 받아서 두 배로 만든 값을 반환해.

Python
result = double(5) print(result)

출력:

예상 결과 / 흐름
10

LangChain의 Runnable도 비슷한 입력 → 처리 → 출력의 구조를 가지고 있어.

다만 Runnable은 단순한 Python 함수 자체가 아니라, 일정한 실행 메서드를 제공하는 LangChain의 공통 인터페이스야.

2-2. Runnable의 공통 메서드

메서드역할학습 시점
invoke()입력 하나를 실행하고 결과 반환이번 강의
batch()여러 입력을 한 번에 처리이후 응용
stream()결과를 나누어 전달2-9강
ainvoke()비동기로 실행2-8강
astream()비동기 스트리밍2-9강

이 메서드들은 Runnable이 제공하는 대표적인 실행 기능이야. 실제 병렬 처리나 스트리밍 방식은 각 구성 요소의 구현에 따라 달라질 수 있어. 공식 문서 ↗

2-3. 우리가 이미 사용한 Runnable

사실 이전 강의에서 배운 객체들도 Runnable 인터페이스를 사용하고 있어.

객체입력출력
ChatPromptTemplate변수 딕셔너리ChatPromptValue
ChatOpenAI메시지 또는 프롬프트AIMessage
StrOutputParser모델 응답str

즉, 각각이 입력과 출력을 가지므로 서로 연결할 수 있는 거야.

이제 가장 중요한 파이프 연산자를 알아보자.

03

파이프 연산자 | 이해하기

3-1. 파이프 연산자란?

다음 코드를 보자.

Python
chain = prompt | model | parser

이 코드는 왼쪽의 출력 결과를 오른쪽의 입력으로 전달하도록 Runnable들을 연결하는 표현이야.

예상 결과 / 흐름
prompt의 출력      ↓model의 입력      ↓model의 출력      ↓parser의 입력      ↓parser의 출력

여기서 |는 Python에 원래 존재하는 연산자이기도 해. 예를 들어 정수에서는 비트 OR 연산으로 사용되지.

하지만 LangChain의 Runnable 객체들은 이 연산자를 재정의해서 실행 단계 연결이라는 의미로 사용할 수 있도록 했어.

참고로 터미널에서 사용하는 |와 겉모습은 같지만, 우리가 배우는 것은 Python 코드 안에서 Runnable 객체를 연결하는 방식이야.

3-2. 연결과 실행은 다르다

여기서 중요한 차이를 이해하자.

Python
chain = prompt | model | parser

이 코드는 실행 흐름을 구성하는 단계야.

이것만으로 실제 OpenAI에 질문을 보내지는 않아.

실제로 실행하려면:

Python
result = chain.invoke({"topic": "Python 함수"})

이렇게 invoke()를 호출해야 해.

즉,

  • |는 어떤 순서로 실행할지 정의
  • chain.invoke()는 정의된 전체 흐름을 실행

이라고 기억하면 돼.

3-3. 파이프 연산자 없이 작성하면?

기존 코드는 다음과 같아.

Python
prompt_value = prompt.invoke({"topic": "Python 함수"}) response = model.invoke(prompt_value) answer = parser.invoke(response)

동일한 흐름을 LCEL로 표현하면:

Python
chain = prompt | model | parser answer = chain.invoke({"topic": "Python 함수"})

훨씬 간결하지?

각 단계가 어떤 입력과 출력을 주고받는지 명확하다면 연결해서 관리하기 편해져.

04

실습 ① RunnableLambda로 연결 원리 배우기

실제 LLM을 호출하기 전에 순수 Python 함수로 원리를 확인해 보자.

이번 실습에서는 RunnableLambda라는 기능을 사용할 거야.

RunnableLambda는 일반 Python 함수를 Runnable처럼 사용할 수 있도록 감싸 주는 클래스야. 공식 문서 ↗

4-1. 실습 파일 만들기

지난 강의와 동일한 langchain-study 프로젝트에 runnable_basic.py 파일을 만들어.

runnable_basic.py
파일 저장 ↓
from langchain_core.runnables import RunnableLambda # 1. 문자열의 앞뒤 공백을 제거하는 함수def remove_spaces(text):    return text.strip() # 2. 인사말을 생성하는 함수def make_greeting(name):    return f"안녕하세요, {name}님!" # 3. 일반 함수를 Runnable로 변환step1 = RunnableLambda(remove_spaces)step2 = RunnableLambda(make_greeting) # 4. 두 단계를 연결chain = step1 | step2 # 5. 체인 실행result = chain.invoke("  철수  ") print(result)

4-2. 실행하기

터미널
uv run python runnable_basic.py

예상 출력:

예상 결과 / 흐름
안녕하세요, 철수님!

이 실습은 OpenAI API를 호출하지 않기 때문에 무료야.

4-3. 코드 한 줄씩 해설

① RunnableLambda 가져오기

Python
from langchain_core.runnables import RunnableLambda

LangChain의 Runnable 기능 중 하나인 RunnableLambda를 가져오는 코드야.

② 첫 번째 함수 정의

Python
def remove_spaces(text):    return text.strip()

remove_spaces()는 문자열을 입력받는 함수야.

text.strip()은 문자열 앞뒤 공백을 제거한 새 문자열을 반환해.

예를 들어:

Python
remove_spaces("  철수  ")

결과는 "철수"야.

③ 두 번째 함수 정의

Python
def make_greeting(name):    return f"안녕하세요, {name}님!"

문자열을 받아 인사말을 만들어 반환해.

make_greeting("철수")는 "안녕하세요, 철수님!"을 반환하지.

④ 일반 함수 Runnable로 변환하기

Python
step1 = RunnableLambda(remove_spaces)step2 = RunnableLambda(make_greeting)

여기서 주의할 점이 있어.

remove_spaces와 make_greeting 뒤에 괄호가 없어.

함수를 지금 실행하는 것이 아니라, 함수 자체를 RunnableLambda에 전달하는 거야.

⑤ 두 단계 연결하기

Python
chain = step1 | step2

첫 번째 Runnable의 출력이 두 번째 Runnable의 입력으로 전달되도록 연결해.

⑥ 전체 체인 실행하기

Python
result = chain.invoke("  철수  ")

실행 흐름은 다음과 같아.

입력

" 철수 "

step1: remove_spaces()

앞뒤 공백 제거

출력: "철수"

step2: make_greeting()

인사말 만들기

출력: "안녕하세요, 철수님\!"

최종 반환값

"안녕하세요, 철수님\!"

이게 바로 LCEL의 가장 기본적인 작동 원리야.

4-4. 체인은 어떤 타입일까?

코드 아래에 다음 내용을 추가해 봐.

Python
print(type(chain).__name__)print(type(result).__name__)

출력:

예상 결과 / 흐름
RunnableSequencestr

chain은 두 개의 Runnable을 연결한 RunnableSequence 객체야.

반면 최종 결과인 result는 문자열인 str이야.

RunnableSequence는 연결된 단계를 순서대로 실행하고, 마지막 단계의 결과를 반환한다는 점을 기억하자.

05

실습 ② Runnable의 입력·출력 타입 확인하기

이번에는 조금 다른 예제를 만들어 보자.

첫 번째 함수는 숫자를 두 배로 만들고, 두 번째 함수는 그 숫자를 문자열로 변환할 거야.

5-1. 전체 코드

runnable_types.py 파일을 만들어.

runnable_types.py
파일 저장 ↓
from langchain_core.runnables import RunnableLambda def double(number):    return number * 2 def format_number(number):    return f"계산 결과는 {number}입니다." step1 = RunnableLambda(double)step2 = RunnableLambda(format_number) chain = step1 | step2 # 각 단계 직접 실행first_result = step1.invoke(5)second_result = step2.invoke(first_result) print("1단계 결과:", first_result)print("1단계 타입:", type(first_result).__name__) print("2단계 결과:", second_result)print("2단계 타입:", type(second_result).__name__) # 전체 체인 실행result = chain.invoke(5) print("최종 결과:", result)print("최종 타입:", type(result).__name__)

5-2. 예상 출력

예상 결과 / 흐름
1단계 결과: 101단계 타입: int 2단계 결과: 계산 결과는 10입니다.2단계 타입: str 최종 결과: 계산 결과는 10입니다.최종 타입: str

5-3. 데이터 타입이 바뀌는 과정

입력 (int)

## 5

double()

숫자를 두 배로 계산

중간 결과: 10 (int)

format_number()

문자열로 변환

최종 결과: "계산 결과는 10입니다." (str)

여기서 매우 중요한 규칙이 있어.

앞 단계의 출력 타입이 다음 단계에서 처리할 수 있는 입력 타입이어야 해.

예를 들어 첫 단계가 리스트를 반환하는데 다음 단계가 정수만 처리하도록 작성되어 있다면 오류가 발생할 수 있어.

우리가 앞으로 만들 AI 체인에서도 이 원리가 똑같이 적용돼.

06

StrOutputParser란 무엇일까?

이제 세 번째 핵심 개념인 StrOutputParser를 배워 보자.

6-1. Output Parser의 역할

Output Parser는 모델이 반환한 결과를 원하는 형태로 처리하는 구성 요소야.

StrOutputParser는 그중 가장 단순한 출력 처리기로, 일반적인 AI 텍스트 응답을 Python 문자열로 추출해 줘.

이전 2-4강에서 배운 코드를 기억해 보자.

Python
response = model.invoke("안녕하세요!") print(response.content)

여기서 response는 AIMessage 객체였어.

그런데 다음처럼 작성하면:

Python
parser = StrOutputParser() answer = parser.invoke(response)

answer는 문자열이 돼.

파싱 전 AIMessage

content: "안녕하세요\!"

usage_metadata: 토큰 정보

response_metadata: 모델 정보

StrOutputParser()

파싱 후 str

"안녕하세요\!"

즉, 일반적인 텍스트 응답에서는 매번 .content에 접근하지 않고 최종 문자열을 바로 받을 수 있게 되는 거야. 공식 문서 ↗

6-2. 실습 ③ API 없이 StrOutputParser 사용하기

parser_basic.py 파일을 만들어.

parser_basic.py
파일 저장 ↓
from langchain_core.messages import AIMessagefrom langchain_core.output_parsers import StrOutputParser # 1. 연습용 AIMessage 생성message = AIMessage(    content="안녕하세요! 저는 Python 선생님입니다.") # 2. 출력 처리기 생성parser = StrOutputParser() # 3. 메시지를 문자열로 변환result = parser.invoke(message) # 4. 타입과 값 확인print("원본 타입:", type(message).__name__)print("변환 타입:", type(result).__name__) print("변환 결과:", result)

실행해 보자.

터미널
uv run python parser_basic.py

예상 결과:

예상 결과 / 흐름
원본 타입: AIMessage변환 타입: str변환 결과: 안녕하세요! 저는 Python 선생님입니다.

이번에는 AIMessage를 직접 만들었으므로 실제 API 요청은 발생하지 않아.

6-3. 코드 한 줄씩 해설

① AIMessage 가져오기

Python
from langchain_core.messages import AIMessage

이전 강의에서 배운 메시지 클래스를 가져오는 코드야.

② StrOutputParser 가져오기

Python
from langchain_core.output_parsers import StrOutputParser

출력 처리기를 사용할 수 있도록 클래스를 가져와.

③ AIMessage 객체 직접 생성하기

Python
message = AIMessage(    content="안녕하세요! 저는 Python 선생님입니다.")

실제 AI 모델을 호출하지 않고 연습용 메시지를 만든 거야.

④ 출력 처리기 객체 만들기

Python
parser = StrOutputParser()

StrOutputParser 클래스의 인스턴스를 생성해.

⑤ 출력 처리기 실행하기

Python
result = parser.invoke(message)

parser도 Runnable 인터페이스를 가지고 있으므로 invoke()로 실행할 수 있어.

입력은 AIMessage이고, 결과는 str이야.

⑥ 반환 타입 확인하기

Python
print(type(result).__name__)

문자열로 변환된 것을 확인할 수 있지.

6-4. StrOutputParser는 언제 사용할까?

예를 들어 모델의 답변을 다음 용도로 활용할 때 편리해.

  • 터미널이나 웹 화면에 텍스트 표시
  • Python의 문자열 메서드로 응답 가공
  • 텍스트 파일에 결과 저장
  • 다른 문자열 처리 함수에 전달

다만 중요한 점이 있어.

StrOutputParser는 JSON 형식을 검증하거나 AI 답변이 사실인지 확인하는 기능이 아니야.

또한 최종 결과가 문자열이므로 모델 응답의 토큰 사용량이나 메타데이터를 그대로 가지고 있지는 않아.

우리는 이번 강의에서 일반적인 텍스트 응답을 다룰 거야.

8-4. 코드를 한 줄씩 해설하기

환경변수 부분은 이전 강의에서 충분히 배웠으므로 핵심 부분을 집중해서 살펴보자.

① 프롬프트 템플릿

Python
prompt = ChatPromptTemplate.from_messages([    ("system", "너는 친절한 Python 선생님이야."),    ("human", "{topic}에 대해 쉽게 설명해 줘.")])

이전에 배운 from_messages()를 이용한 코드야.

{topic}이라는 템플릿 변수가 있어.

아직 실제 값은 전달하지 않은 상태야.

② 모델 객체 생성

Python
model = ChatOpenAI(model="gpt-5.4-mini")

OpenAI 모델을 사용하는 객체를 생성해.

이 시점에는 일반적으로 실제 답변 생성 요청이 발생하지 않아.

③ 출력 처리기 생성

Python
parser = StrOutputParser()

모델 응답을 문자열로 변환할 처리기를 준비해.

④ 체인 생성

Python
chain = prompt | model | parser

가장 중요한 부분이야.

세 Runnable을 왼쪽에서 오른쪽으로 연결했어.

이 코드를 작성했다고 해서 세 단계를 즉시 실행하는 것은 아니야.

⑤ 전체 체인 실행

Python
answer = chain.invoke({    "topic": "Python 함수"})

딕셔너리로 입력값을 전달해.

Python 문법에서:

Python
{"topic": "Python 함수"}

는 "topic"이라는 키에 "Python 함수"라는 문자열 값이 대응하는 딕셔너리야.

이 값을 전달하면 내부에서 다음 순서로 처리돼.

  1. prompt가 {topic}에 "Python 함수"를 대입해.
  2. model이 완성된 프롬프트를 받아 실제 AI 답변을 생성해.
  3. parser가 모델 응답에서 텍스트를 추출해.
  4. 최종 문자열이 answer에 저장돼.

⑥ 결과 출력

Python
print(answer)

이미 answer가 문자열이기 때문에 .content가 필요 없어.

이전 코드와 비교하면 다음과 같아.

Python
# StrOutputParser가 없는 경우response = model.invoke(messages)print(response.content)
Python
# StrOutputParser가 있는 경우answer = chain.invoke({"topic": "Python 함수"})print(answer)

이 차이를 반드시 기억하자.

실습 ⑤ 각 단계의 실제 타입 확인하기

이번에는 LCEL이 내부적으로 어떤 값을 전달하는지 직접 살펴보자.

앞에서 만든 프롬프트, 모델, 출력 처리기 객체가 이미 있다고 가정할게.

Python
prompt_value = prompt.invoke({    "topic": "Python 함수"}) print(type(prompt_value).__name__)

예상 출력:

예상 결과 / 흐름
ChatPromptValue

이 단계까지는 API 요청이 없어.

다음 단계에서는 실제 모델을 호출해.

Python
response = model.invoke(prompt_value) print(type(response).__name__)

예상 출력:

예상 결과 / 흐름
AIMessage

마지막으로 출력 처리기를 호출해.

Python
answer = parser.invoke(response) print(type(answer).__name__)

예상 출력:

예상 결과 / 흐름
str

이 방식은 모델 API 호출을 한 번만 수행해.

반면 이 코드를 실행한 후 별도로 chain.invoke(...)를 다시 실행하면 추가 API 요청이 발생하므로 비용에 주의해야 해.

각 단계 비교

코드결과 타입실제 LLM 호출
prompt.invoke(data)ChatPromptValue없음
model.invoke(prompt_value)AIMessage있음
parser.invoke(response)str없음
chain.invoke(data)str전체 체인에서 한 번

여기까지 이해했다면 LCEL의 가장 중요한 실행 구조를 이해한 거야.

10

LCEL에서 자주 발생하는 오류와 해결 방법

오류 ① 문자열 결과에 .content를 사용하는 경우

다음 코드를 보자.

Python
chain = prompt | model | parser answer = chain.invoke({"topic": "Python 함수"}) print(answer.content)

마지막 줄에서 다음과 같은 오류가 발생할 수 있어.

예상 결과 / 흐름
AttributeError: 'str' object has no attribute 'content'

왜 그럴까?

StrOutputParser를 거친 결과는 str이기 때문이야.

문자열에는 AIMessage의 content 속성이 없어.

올바른 방법:

Python
print(answer)

반대로 StrOutputParser가 없는 경우에는:

Python
chain = prompt | model response = chain.invoke({"topic": "Python 함수"}) print(response.content)

이렇게 사용할 수 있어.

오류 ② 프롬프트 변수를 빠뜨린 경우

다음 템플릿을 생각해 보자.

Python
prompt = ChatPromptTemplate.from_messages([    ("system", "너는 {language} 선생님이야."),    ("human", "{topic}에 대해 설명해 줘.")])

여기서는 language, topic 두 변수가 필요해.

그런데 다음처럼 호출하면:

Python
chain.invoke({"topic": "함수"})

language 값이 없어서 KeyError가 발생할 수 있어.

수정한 코드:

Python
chain.invoke({    "language": "Python",    "topic": "함수"})

실제 API 요청을 보내기 전에 필요한 변수를 확인하고 싶다면 다음 코드를 사용할 수 있어.

Python
print(prompt.input_variables)

오류 ③ Runnable 연결 순서가 잘못된 경우

Python
chain = prompt | parser | model

이 코드에서는 ChatPromptTemplate의 출력이 StrOutputParser로 먼저 전달돼.

하지만 StrOutputParser는 모델 응답에서 텍스트를 추출하는 도구이므로 일반적인 ChatPromptValue를 처리하는 단계에 놓는 것이 적절하지 않아.

올바른 순서는 다음과 같아.

Python
chain = prompt | model | parser

각 단계가 무엇을 입력받고 무엇을 반환하는지 먼저 생각하는 습관이 중요해.

오류 ④ StrOutputParser 객체를 생성하지 않은 경우

다음 두 코드를 비교해 보자.

Python
parser = StrOutputParser
Python
parser = StrOutputParser()

첫 번째는 클래스 자체를 변수에 저장한 것이고, 두 번째는 인스턴스를 생성한 거야.

우리는 다음과 같이 실제 객체를 생성해서 사용해야 해.

Python
parser = StrOutputParser()chain = prompt | model | parser

오류 ⑤ API 키 또는 인증 오류

다음과 같은 오류가 발생할 수 있어.

예상 결과 / 흐름
AuthenticationErrorRateLimitErrorAPIConnectionError

앞선 강의에서 배운 것처럼 .env 파일, API 키, 결제 설정, 네트워크 연결을 확인해야 해.

LCEL을 사용한다고 해서 OpenAI API의 인증이나 사용 한도 관리가 없어지는 것은 아니야.

오류 ⑥ 토큰 사용량을 확인할 수 없는 경우

이 코드를 실행한다고 해 보자.

Python
chain = prompt | model | parser answer = chain.invoke({"topic": "함수"})

여기서 answer는 문자열이야.

따라서 다음 코드는 사용할 수 없어.

Python
print(answer.usage_metadata)

토큰 사용량이 필요하다면 AIMessage 단계에서 정보를 확인해야 해.

예를 들어:

Python
prompt_value = prompt.invoke({"topic": "함수"})response = model.invoke(prompt_value) print("토큰 사용량:", response.usage_metadata) answer = parser.invoke(response)print("답변:", answer)

이 코드는 모델을 한 번만 호출하면서 토큰 정보와 최종 문자열을 모두 확인할 수 있어.

실제 서비스에서는 실행 추적 도구나 콜백을 이용해 사용량을 수집하는 방법도 있어. 지금은 이 정도만 이해하면 충분해.
