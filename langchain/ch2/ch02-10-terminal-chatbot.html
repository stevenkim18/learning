코드는 복사하거나 파일 저장 버튼으로 내려받아 터미널에서 실행해. 실제 모델을 호출하는 예제는 API 키와 인터넷 연결이 필요하고 사용 요금이 발생할 수 있어.

01

이번 프로젝트의 완성 목표

완성할 프로그램은 다음 기능을 제공해.

  • 사용자 질문을 입력받고 빈 입력은 건너뛴다.
  • System 지시, 이전 대화, 새 질문을 프롬프트로 구성한다.
  • 일반 응답과 스트리밍 응답을 선택한다.
  • 정상 완료한 사용자·AI 대화 쌍을 저장한다.
  • 최근 대화만 유지한다.
  • /help, /history, /reset, /exit 명령을 처리한다.

이 프로젝트의 대화 기록은 Python 메모리의 리스트야. 프로그램을 종료하면 초기화돼. 파일이나 DB에 영구 저장하는 기능은 포함하지 않아.

03

먼저 input() 반복문으로 원리 익히기

repl_demo.py 파일에 다음 코드를 저장해. 이 코드는 표준 Python만 사용하고 실제 AI를 호출하지 않아.

repl_demo.py
파일 저장 ↓
while True:    question = input("사용자: ").strip()    if question.lower() in ("quit", "exit"):        print("대화를 종료합니다.")        break    if not question:        print("질문을 입력해 주세요.")        continue    print("연습 응답:", question, "라는 질문을 받았습니다.")
터미널
uv run python repl_demo.py
코드해설
while True종료 조건을 만날 때까지 입력 반복
input().strip()사용자 문자열을 받고 앞뒤 공백 제거
lower()영문 종료 명령의 대소문자 차이를 줄임
break반복문을 끝냄
continue이번 반복의 나머지를 건너뛰고 다시 입력받음

반복문 자체가 AI를 부르는 것은 아니야. 질문을 모델에 전달하는 실행 메서드를 코드에 추가해야 모델 호출이 발생해.

04

메시지와 대화 기록 설계

프롬프트는 System 메시지, 이전 대화, 새 Human 메시지 순서로 구성해.

Python
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder prompt = ChatPromptTemplate.from_messages([    ("system", "너는 친절한 Python 선생님이야."),    MessagesPlaceholder("history"),    ("human", "{question}")])

MessagesPlaceholder("history")는 문자열 하나를 넣는 자리가 아니라 여러 메시지 객체로 된 리스트를 넣는 자리야.

Python
inputs = {"history": history, "question": question}

history가 빈 리스트이면 System과 새 Human 메시지만 만들어져. 대화 쌍이 있다면 그 사이에 과거의 Human·AI 메시지가 들어가.

System 지시는 템플릿 안에 있으므로 /reset으로 history를 비워도 유지돼. 과거 대화 리스트에는 System 메시지를 별도로 넣지 않는 설계야.

실제 모델과 데모 모델 구분하기

실제 모델은 ChatOpenAI로 만들고, 데모는 FakeListChatModel을 사용해. 데모 모델은 준비된 응답 문자열을 차례대로 반환하는 연습용 모델이야.

Python
from langchain_core.language_models.fake_chat_models import FakeListChatModel model = FakeListChatModel(responses=[    "[데모] 질문을 받았어. 이 문장은 미리 준비된 응답이야.",    "[데모] 대화 목록에 앞선 질문과 답변이 함께 저장돼."])

데모에는 언어 이해나 실제 추론 능력이 없어. 앞선 대화를 의미적으로 이해했는지 평가하는 용도가 아니라 입력·출력 타입, 대화 저장과 명령 처리를 확인하는 용도야.

실제 모델로 실행할 때는 2-3강의 .env에 API 키를 준비하고 --live를 명시해. 데모는 실제 키가 없어도 동작해.

다음 순서로 입력해 봐.

예상 결과 / 흐름
/helpPython 함수가 뭐야?/history/reset/history/exit

첫 질문에는 [데모]로 시작하는 고정 응답이 나와. 첫 /history에는 Human과 AI 메시지 2개가 표시되고, /reset 후에는 저장된 메시지 수가 0이 돼.

데모 모드의 출력과 실제 모델의 생성 답변을 혼동하지 말자. 실제 대화 내용에 맞는 답변을 받으려면 별도로 준비한 API 키로 --live 모드를 실행해야 해.

10

build_chain()의 처리 순서

live가 참일 때만 .env를 읽고 실제 모델을 만들어. 거짓이면 데모 모델을 만들지.

그 다음 두 모드 모두 같은 프롬프트 구조를 사용하고 prompt | model을 반환해. 출력 타입이 AIMessage이므로 이후의 대화 기록 처리 코드를 공통으로 사용할 수 있어.

Python
return prompt | model

이 줄은 체인을 만드는 단계야. 아직 새 질문에 대한 모델 실행은 발생하지 않아. 이후의 chain.invoke(inputs) 또는 chain.stream(inputs)에서 실행돼.

MessagesPlaceholder("history")와 입력 딕셔너리의 "history"는 이름이 같아야 해. "{question}"과 "question"도 마찬가지야.

11

reply_once()와 출력 타입 이해하기

일반 모드에서는 chain.invoke()의 AIMessage를 그대로 반환해. 스트리밍 모드에서는 AIMessageChunk들을 모은 뒤 AIMessage로 변환해.

따라서 호출한 쪽에서는 두 경우 모두 메시지 객체로 다룰 수 있어. 문자열만 모으고 이를 AIMessage처럼 사용하면 .type, .content 또는 메타데이터 처리에서 혼동이 생길 수 있어.

Python
inputs = {"history": list(history), "question": question}

list(history)는 현재 리스트의 얕은 복사본을 만들어 입력으로 사용해. 메시지 내용을 새로 생성하는 것은 아니야. 이번 프로그램은 한 번에 질문 하나를 처리하므로 실행 중 대화 기록을 다른 작업이 수정하지 않아.

스트리밍 화면에 이미 글자가 보였더라도 오류로 끝났으면 reply_once()는 정상 응답을 반환하지 않아. 아래 저장 단계에 도달하지 않으므로 그 질문은 기록에 추가되지 않아.

12

성공한 대화 쌍만 저장하고 제한하기

Python
history.extend([HumanMessage(content=question), response])history = trim_history(history)

extend([...])는 리스트의 각 항목을 기존 리스트 끝에 추가해. 이번에는 사용자 메시지와 AI 응답, 두 개를 추가해.

Python
return history[-2 * KEEP_TURNS:]

대화 한 쌍은 메시지 2개이므로 최근 4쌍은 최대 8개 메시지야. 리스트 슬라이싱의 [-8:]은 뒤에서부터 최대 8개를 가져와. 리스트가 그보다 짧으면 있는 항목만 반환해.

대화 쌍 단위로 잘라 사용자와 AI의 발화 순서를 유지해. 이 단순한 개수 제한은 토큰 단위의 정밀한 컨텍스트 관리와는 달라. 메시지 하나가 매우 길 수도 있으므로 실제 서비스에서는 토큰 수와 요약 전략도 고려해야 해.

13

명령과 오류 처리를 이해하기

continue가 있는 명령 처리 분기는 모델 실행 코드에 도달하지 않고 다음 입력으로 이동해. /reset은 history.clear()만 실행하므로 템플릿에 있는 기본 역할은 그대로 남아.

except EOFError는 입력이 종료된 경우를 처리해. 바깥의 except KeyboardInterrupt는 Ctrl+C로 종료한 경우 안내 문구를 출력해.

완성 기준과 CH 02 마무리

다음을 직접 확인하면 이번 장의 목표를 달성한 거야.

  • 데모 모드에서 질문과 종료 명령을 처리한다.
  • /history에서 사용자·AI 메시지 쌍을 확인한다.
  • /reset 후 기록은 비워지지만 기본 역할은 유지된다.
  • 최근 대화 쌍 수를 바꾸어 보관 개수를 조절한다.
  • 일반 응답과 스트리밍 응답의 타입과 처리 차이를 설명한다.
  • 실제 호출을 선택할 때만 API 키와 사용량에 따른 비용이 필요함을 안다.

CH 02에서는 환경 준비부터 첫 호출, 메시지, 프롬프트, LCEL, 비동기와 스트리밍까지 연결했어. 다음 CH 03에서는 출력 형식, 구조화된 응답과 모델 결과를 프로그램에서 활용하는 방법으로 확장할 수 있어.

지금 만든 프로그램은 학습용 기반이야. 외부 사용자용 서비스에는 인증, 사용자별 대화 분리, 영속 저장과 요청 제한 등을 요구사항에 맞게 추가해야 해.
