02

OpenAI API 키란?

2-1. API부터 이해하기

API는 Application Programming Interface의 약자야.

쉽게 말해 프로그램이 다른 프로그램의 기능을 사용할 수 있도록 제공하는 연결 규칙이라고 이해하면 돼.

예를 들어 우리가 만드는 Python 프로그램에서 GPT 모델을 사용하려면 OpenAI API를 호출할 수 있어.

예상 결과 / 흐름
내 Python 프로그램       ↓OpenAI API 요청       ↓OpenAI의 GPT 모델       ↓응답 반환       ↓내 Python 프로그램

이때 OpenAI는 요청한 프로그램이 API를 사용할 권한이 있는지 확인해야 해.

그 역할을 하는 비밀 인증 정보가 바로 API 키야.

2-2. API 키는 비밀번호와 비슷해

API 키를 건물의 출입 카드라고 생각하면 쉬워.

  • 출입 카드가 있으면 허용된 구역에 들어갈 수 있어.
  • API 키가 있으면 허용된 API 기능을 호출할 수 있어.
  • 카드가 유출되면 다른 사람이 사용할 수 있어.
  • API 키가 유출되면 다른 사람이 내 계정의 API 사용량을 발생시킬 수 있어.

따라서 API 키는 일반적인 설정값이 아니라 외부에 공개하면 안 되는 비밀 정보야. API 인증과 비밀키 ↗

2-3. ChatGPT 구독과 API는 별개일까?

응. 기본적으로 별개의 결제 체계야.

구분ChatGPTOpenAI API
주요 용도ChatGPT에서 직접 대화Python 등에서 AI 기능 개발
사용 방법웹이나 앱API 요청
인증ChatGPT 로그인API 키 등
결제ChatGPT 요금제별도 API 결제 체계

일부 구독에는 별도 프로모션 API 크레딧이 제공될 수도 있지만, ChatGPT 유료 구독이 곧 무제한 API 사용 권한을 뜻하지는 않아. 구독과 API 크레딧 ↗

현재 자격을 충족하는 일부 ChatGPT Pro·Business 구독에는 API 크레딧을 연결하는 혜택도 있어. API 키로 호출한 사용량은 연결된 API 조직의 크레딧과 결제 설정을 기준으로 처리돼. 적용 조건은 공식 API 크레딧 안내에서 확인할 수 있어.

이번 강의에서는 실제 API 요청을 보내지 않으므로 API 키 저장과 로딩을 연습하는 데 요금이 발생하지 않아.

03

OpenAI API 키 발급하기

API 키는 OpenAI 개발자 플랫폼에서 발급받을 수 있어.

OpenAI API KeysAPI 키 생성 및 관리 페이지API 키 관리 페이지 열기 ↗

3-1. 발급 절차

  1. OpenAI 개발자 플랫폼에 로그인해.
  2. API 키를 만들 프로젝트를 선택해. 학습 전용 프로젝트를 만들어도 좋아.
  3. API Keys 메뉴로 이동해.
  4. Create new secret key를 선택해.
  5. 이름을 지정하고, 제공되는 권한 설정을 확인한 후 키를 생성해.
  6. 생성된 API 키를 안전한 장소에 복사해.

API 키의 전체 비밀값은 생성할 때만 표시될 수 있어. 잃어버렸다면 기존 키를 다시 확인하는 대신 새 키를 발급받아야 해. API 키 시작 안내 ↗키 조회 참고 ↗

참고: API 키를 생성할 권한이 없는 조직 계정이라면 프로젝트 관리자에게 권한을 요청해야 할 수도 있어.

3-2. API 키를 발급받았다면

키는 일반적으로 긴 문자열 형태야.

예상 결과 / 흐름
sk-...생략...

실제 키의 형식이나 접두사는 달라질 수 있으므로 특정 문자열로 시작하는지만 보고 유효성을 판단하면 안 돼.

중요: 발급받은 실제 API 키를 이 채팅에 입력하거나 공유하지 마. 앞으로 만들 .env 파일에 직접 저장하면 돼.

추가로 API 사용량과 결제 설정은 OpenAI API 결제 관리 페이지 ↗에서 확인할 수 있어.

04

환경변수(Environment Variable)란?

이제 이번 강의의 핵심 개념이야.

4-1. 일반 Python 변수와 비교하기

우리는 이전 Python 강의에서 다음처럼 변수를 만들었어.

Python
name = "Python"print(name)

여기서 name은 Python 프로그램 안에서 사용하는 변수야.

반면 환경변수는 운영체제나 실행 환경이 프로그램에 전달하는 이름과 값의 쌍이야.

예를 들어:

예상 결과 / 흐름
APP_MODE=developmentLOG_LEVEL=INFOOPENAI_API_KEY=비밀_키

환경변수를 사용하면 코드와 설정을 분리할 수 있어.

다음과 같이 프로그램을 구성할 수 있지.

Python 코드

Python
api_key = os.getenv(    "OPENAI_API_KEY")

키의 실제 값이 코드에 들어가지 않음

환경 설정

예상 결과 / 흐름
OPENAI_API_KEY=  비밀_키

실제 값은 별도로 보관

위 환경 설정은 구조를 설명하기 위한 표기야. 실제 .env 파일에서는 이름과 값을 같은 줄에 작성해. 정확한 예시는 6-3에서 확인하자.

이렇게 분리하면 개발 환경과 운영 환경에서 서로 다른 키를 사용할 수도 있어.

4-2. Python에서 환경변수 읽기

Python에는 os라는 기본 모듈이 있어.

Python
import os

환경변수는 다음과 같이 읽을 수 있어.

Python
value = os.getenv("APP_MODE")

os.getenv()는 이름에 해당하는 환경변수를 찾아서 값을 반환하는 함수야.

환경변수가 없다면 기본적으로 None을 반환해.

기본값을 지정하는 방법도 있어.

Python
mode = os.getenv("APP_MODE", "study")

이 코드는 APP_MODE가 없으면 "study"를 사용하라는 뜻이야.

참고로 환경변수 값은 문자열로 다뤄지기 때문에 숫자나 참/거짓 값이 필요하다면 별도로 변환해야 해.

05

.env 파일이란?

.env는 환경변수에 사용할 설정값을 저장하는 텍스트 파일이야.

여기서 중요한 차이점을 알아두자.

.env 파일 자체가 환경변수는 아니야. 파일에 적힌 값을 실제 프로그램의 환경변수로 읽어들이는 과정이 필요해.

우리는 이를 위해 python-dotenv를 사용할 거야.

개념역할
.env설정값을 텍스트로 저장하는 파일
python-dotenv.env 파일을 읽는 Python 패키지
load_dotenv().env 내용을 환경변수로 불러오는 함수
os.getenv()환경변수의 값을 읽는 함수

python-dotenv는 기존 환경변수를 기본적으로 덮어쓰지 않는 방식으로 동작해. python-dotenv 공식 문서 ↗

6-2. 먼저 .gitignore 설정하기

API 키를 저장하기 전에 .gitignore부터 확인하자.

.gitignore는 Git이 특정 파일을 추적하지 않도록 설정하는 파일이야.

프로젝트의 .gitignore 파일에 다음 항목을 추가해.

.gitignore
.venv/.env.env.*!.env.example

각 줄의 의미는 다음과 같아.

설정의미
.venv/가상환경 폴더 제외
.env실제 환경변수 파일 제외
.env.*.env.local 같은 추가 환경설정 파일 제외
!.env.example비밀값이 없는 예제 파일은 포함 가능

기존에 다른 항목이 있다면 삭제하지 말고 위 내용을 추가하면 돼.

주의할 점은 .gitignore가 이미 Git에 커밋한 비밀키를 지워주지는 않는다는 것이야.

6-3. .env 파일 생성하기

VS Code에서 프로젝트 폴더를 마우스 오른쪽 버튼으로 클릭하고 새 파일을 만들어.

파일 이름은 정확히 다음과 같이 지정해.

예상 결과 / 흐름
.env

확장자 .txt를 붙이면 안 돼.

그리고 다음 내용을 작성해.

.env 설정 예시
APP_MODE=studyOPENAI_API_KEY=put_your_real_api_key_here

put_your_real_api_key_here는 실제 API 키가 아니라 자리표시자야.

API 키를 이미 발급받았다면 해당 부분을 자신의 키로 교체해. 아직 발급받지 않았다면 그대로 두고 환경변수 실습부터 진행해도 돼.

이 파일에서는 변수 이름과 값을 =로 구분해.

  • APP_MODE: 우리가 임의로 만든 실행 모드 설정
  • OPENAI_API_KEY: OpenAI API 인증에 사용할 비밀키의 환경변수 이름

일반적으로 = 양옆에 공백을 넣지 않고 작성하는 습관을 들이면 좋아.

6-4. 프로젝트 파일 구조 확인하기

지금까지 올바르게 진행했다면 주요 폴더 구조는 다음과 비슷해.

예상 결과 / 흐름
langchain-study/├── .venv/├── .env                 # 비밀 설정값├── .gitignore├── .python-version├── main.py├── check_env.py├── pyproject.toml└── uv.lock

여기서 .env와 .gitignore는 완전히 다른 역할을 한다는 점을 기억하자.

실습 ② python-dotenv로 환경변수 불러오기

이제 Python에서 .env 파일을 읽어 보자.

7-1. 새 Python 파일 작성하기

프로젝트 폴더에 check_api_key.py 파일을 만들어.

langchain-study/
  • .env
  • check_api_key.py (새로 만들 파일)
  • … 기존 프로젝트 파일

.env와 Python 파일을 같은 폴더에 두자.

7-2. 전체 코드 작성하기

check_api_key.py
파일 저장 ↓
import osfrom pathlib import Path from dotenv import load_dotenv # 현재 Python 파일과 같은 폴더에 있는 .env 파일 경로env_path = Path(__file__).resolve().parent / ".env" # .env 파일을 환경변수로 불러오기load_dotenv(dotenv_path=env_path) # 환경변수 읽기app_mode = os.getenv("APP_MODE", "development")api_key = os.getenv("OPENAI_API_KEY") # 결과 확인print("실행 모드:", app_mode) if not api_key or api_key == "put_your_real_api_key_here":    print("OpenAI API 키가 아직 설정되지 않았습니다.")else:    print("OpenAI API 키를 읽었습니다.")    print("실제 API 인증 여부는 아직 확인하지 않았습니다.")

이 코드는 실제 API를 호출하지 않아. 따라서 올바른 키인지 확인하는 프로그램이 아니라 환경변수를 정상적으로 읽어오는지 확인하는 프로그램이야.

7-3. 코드 한 줄씩 해설

① os 모듈 가져오기

Python
import os

os는 Python의 표준 라이브러리야.

운영체제와 관련된 기능을 제공하고, 그중에서 우리가 사용할 기능은 환경변수 읽기야.

② Path 클래스 가져오기

Python
from pathlib import Path

pathlib는 파일이나 폴더의 경로를 다루는 Python 표준 라이브러리야.

예를 들어 Windows의 경로와 macOS의 경로 표기 방식은 다를 수 있는데, Path를 사용하면 운영체제에 맞게 경로를 다루기 편해.

③ load_dotenv 함수 가져오기

Python
from dotenv import load_dotenv

우리가 설치한 python-dotenv 패키지에서 load_dotenv라는 함수를 가져오는 코드야.

여기서 주의할 점이 있어.

설치할 때의 패키지 이름은 python-dotenv지만, Python 코드에서 가져올 때는 dotenv를 사용해.

④ .env 파일 경로 만들기

Python
env_path = Path(__file__).resolve().parent / ".env"

이 줄이 조금 어려울 수 있으니 나누어 보자.

코드의미
__file__현재 실행 중인 Python 소스 파일의 경로
Path(__file__)경로를 Path 객체로 만들기
.resolve()절대경로로 변환하기
.parent현재 파일이 위치한 폴더 가져오기
/ ".env"그 폴더 안의 .env 파일 경로 만들기

예를 들어 현재 파일이 다음 위치에 있다고 생각해 보자.

예상 결과 / 흐름
C:\projects\langchain-study\check_api_key.py

그러면 env_path는 다음 파일을 가리키게 돼.

예상 결과 / 흐름
C:\projects\langchain-study\.env

이렇게 하면 터미널의 현재 작업 위치에 덜 의존하도록 만들 수 있어.

⑤ .env 파일 읽기

Python
load_dotenv(dotenv_path=env_path)

이번 강의의 핵심 코드야.

load_dotenv()는 지정한 .env 파일을 읽어서 변수들을 현재 Python 프로세스의 환경변수에 추가해.

dotenv_path=env_path는 앞에서 만든 경로를 함수에 전달한다는 뜻이야.

간단한 프로그램에서는 다음처럼 작성해도 돼.

Python
load_dotenv()

이 경우 python-dotenv가 .env 파일을 자동으로 찾아. 이번 실습에서는 파일 위치를 명확하게 지정하는 방식을 사용할 거야.

⑥ 환경변수 가져오기

Python
app_mode = os.getenv("APP_MODE", "development")

.env에 APP_MODE=study가 저장되어 있다면 app_mode에는 "study"가 들어가.

APP_MODE가 없다면 "development"가 기본값으로 사용돼.

다음 코드도 살펴보자.

Python
api_key = os.getenv("OPENAI_API_KEY")

이 코드에서는 OPENAI_API_KEY라는 환경변수를 읽어서 api_key 변수에 저장해.

환경변수가 없다면 None이 반환돼.

⑦ API 키가 설정되었는지 확인하기

Python
if not api_key or api_key == "put_your_real_api_key_here":    print("OpenAI API 키가 아직 설정되지 않았습니다.")

여기서는 두 가지 조건을 확인해.

첫 번째는 not api_key야. 키가 None이거나 빈 문자열이면 참이 돼.

두 번째는 실제 키 대신 연습용 자리표시자가 들어 있는지 확인하는 조건이야.

둘 중 하나라도 참이면 아직 키가 설정되지 않았다고 안내해.

⑧ 실제 키 값은 출력하지 않기

Python
else:    print("OpenAI API 키를 읽었습니다.")    print("실제 API 인증 여부는 아직 확인하지 않았습니다.")

이 부분이 보안상 중요해.

다음과 같이 작성하면 안 돼.

피해야 하는 예 · Python
# 보안상 피해야 하는 코드print(api_key)

실제 API 키를 출력하면 터미널 기록, 로그, 화면 공유 등을 통해 비밀값이 유출될 수 있어.

그리고 환경변수를 읽는 데 성공하더라도 키가 실제로 유효한지, 해당 프로젝트에 사용 권한이나 잔액이 있는지는 아직 알 수 없어.

실습 ③ 환경변수가 어떻게 달라지는지 확인하기

환경변수는 직접 값을 바꿔 보는 것이 이해에 가장 좋아.

8-1. APP_MODE 값 변경하기

.env 파일에서 다음 내용을:

.env 설정 예시
APP_MODE=study

이렇게 변경해 봐.

.env 설정 예시
APP_MODE=production

이제 프로그램을 다시 실행해.

터미널
uv run python check_api_key.py

정상적으로 반영됐다면 다음처럼 나타나.

예상 결과 / 흐름
실행 모드: production

여기서 production은 단순히 우리가 설정한 문자열이야. 실제 운영 서버로 전환되는 것은 아니야.

Python 코드를 수정하지 않고 설정 파일만 바꿔도 프로그램의 동작에 필요한 설정값을 바꿀 수 있다는 점이 중요해.

8-2. 기본값 확인하기

이번에는 .env 파일에서 APP_MODE 줄을 주석 처리해 보자.

.env 설정 예시
# APP_MODE=production

다시 실행하면 어떻게 될까?

예상 결과 / 흐름
실행 모드: development

앞서 다음과 같이 코드를 작성했기 때문이야.

Python
app_mode = os.getenv("APP_MODE", "development")

단, 운영체제에 APP_MODE가 이미 설정되어 있다면 그 값이 사용될 수 있어.

8-3. 기존 환경변수와 .env 값이 충돌하면?

python-dotenv의 기본 동작에서는 이미 존재하는 환경변수를 .env 값으로 덮어쓰지 않아.

예를 들어 운영체제에 다음 값이 설정되어 있다고 생각해 보자.

예상 결과 / 흐름
APP_MODE=server

그런데 .env에는 다음과 같이 적혀 있어.

.env 설정 예시
APP_MODE=study

기본 load_dotenv()를 사용하면 기존 환경변수인 server가 우선해.

이 특징은 나중에 로컬 개발과 실제 서버 환경을 구분할 때 유용해. python-dotenv 공식 문서 ↗

APP_MODE는 어디에서 읽힐까?

본문의 세 가지 상황을 비교해 봐. 고정된 학습용 값으로만 동작하며 실제 .env 파일이나 컴퓨터의 환경변수를 읽지 않아.

기존 환경변수없음
.env의 APP_MODEstudy
os.getenv() 결과study

기존 환경변수가 없으므로 .env의 study를 읽어.

꼭 알아야 할 API 키 보안 원칙

OpenAI도 공식적으로 환경변수 사용, 비밀키 공유 금지, 클라이언트 코드에 키 삽입 금지 등을 권장하고 있어. API 인증과 비밀키 ↗

Python 소스 코드에 API 키를 직접 작성하지 않기

api_key = "실제키"처럼 코드에 직접 작성하면 코드 공유 과정에서 노출될 수 있어. 환경변수나 비밀 관리 도구를 사용하자.

.env 파일을 Git에 올리지 않기

.gitignore에 .env를 추가해. 실제로 Git에 추적 중인지 확인하려면 프로젝트 폴더에서 다음 명령어를 실행할 수 있어.

터미널
git ls-files -- .env

아무것도 출력되지 않으면 현재 Git이 .env를 추적하고 있지 않은 거야. Git 저장소가 초기화된 프로젝트에서 사용해야 해.

웹 브라우저나 모바일 앱 코드에 키를 포함하지 않기

React, Next.js 클라이언트 컴포넌트, 브라우저 JavaScript 등에 비밀키를 넣으면 사용자가 확인할 수 있어. 실제 서비스를 만들 때는 서버 측에서 키를 보관하고 API를 호출해야 해.

실제 운영 서비스에서는 비밀 관리 서비스를 고려하기

.env는 암호화된 보관소가 아니라 일반 텍스트 파일이야. 로컬 개발용으로는 편리하지만 운영 환경에서는 호스팅 플랫폼의 Secret 설정이나 전용 비밀 관리 서비스를 사용하는 것이 좋아.

API 키가 유출되었다면 즉시 교체하기

해당 키를 OpenAI 개발자 플랫폼에서 폐기하고 새 키를 발급받아야 해. Git 기록에 올라간 경우 단순히 파일을 삭제하는 것만으로 충분하지 않아. 사용량에 이상이 없는지도 확인해야 해.

자주 발생하는 오류와 해결 방법

오류 ① No module named 'dotenv'

예상 결과 / 흐름
ModuleNotFoundError: No module named 'dotenv'

원인: python-dotenv 패키지가 설치되지 않았거나 다른 Python 환경으로 실행했을 수 있어.

해결:

터미널
uv add python-dotenvuv run python check_api_key.py

오류 ② API 키를 입력했는데 없다고 나옴

가장 먼저 다음 사항을 확인해.

  • .env 파일이 check_api_key.py와 같은 폴더에 있는가?
  • 파일 이름이 .env.txt가 아닌가?
  • 변수 이름이 정확히 OPENAI_API_KEY인가?
  • = 뒤에 실제 키를 입력했는가?
  • 기존 운영체제 환경변수가 예상과 다른 값으로 설정되어 있지 않은가?

Windows에서는 파일 확장자가 숨겨져 있을 수 있어. VS Code에서 파일 이름을 직접 확인하는 것이 좋아.

오류 ③ load_dotenv()를 실행했는데 값이 None임

다음 순서를 확인해 봐.

Python
from dotenv import load_dotenvimport os load_dotenv() print(os.getenv("APP_MODE"))

.env가 실제로 존재하고 올바른 위치에 있는지 확인해야 해.

우리가 작성한 완성 코드처럼 Path(__file__).resolve().parent로 경로를 지정하는 방식도 도움이 돼.

오류 ④ API 키를 읽었는데 실제 요청에서 인증 오류가 발생함

이번 강의의 코드는 API 키가 존재하는지만 확인해.

다음 강의에서 API 호출을 할 때 인증 오류가 발생한다면 실제 키가 올바른지, 폐기되지는 않았는지, 해당 프로젝트에서 API 사용 권한이 있는지 확인해야 해.

결제 또는 사용량 제한 오류는 인증 오류와 원인이 다를 수 있어.
