01

먼저 uv가 무엇인지 이해하기

1-1. uv란?

uv는 Python 버전, 패키지, 가상환경, 프로젝트 의존성을 관리하는 도구야.

기존 Python 개발에서는 여러 도구를 함께 사용하기도 했어.

기존 도구역할uv에서 주로 사용하는 명령어
pyenvPython 버전 관리uv python
venv가상환경 생성uv venv
pip패키지 설치uv add
pip-tools 등의존성 버전 관리uv lock
pythonPython 코드 실행uv run python

uv는 이런 작업을 하나의 도구에서 처리할 수 있고, Rust로 구현되어 빠른 패키지 관리 기능을 제공해. uv 개요 ↗프로젝트 가이드 ↗

1-2. 패키지가 무엇일까?

Python에서 패키지(Package)는 다른 개발자들이 만들어 놓은 기능을 가져다 쓸 수 있도록 배포한 코드 묶음이야.

예를 들어:

Python
from langchain_openai import ChatOpenAI

이 코드는 외부 라이브러리의 ChatOpenAI 클래스를 가져오는 코드야.

이 코드를 실행하려면 먼저 langchain-openai라는 패키지가 설치되어 있어야 해.

그래서 우리가 uv를 사용하는 거야.

1-3. 가상환경은 왜 필요할까?

여기서 꼭 이해해야 하는 개념이 있어.

바로 가상환경(Virtual Environment)이야.

예를 들어 컴퓨터에서 두 프로젝트를 개발한다고 생각해 보자.

프로젝트 A

LangChain 학습

.venv패키지 버전 1.x

프로젝트 B

기존 AI 서비스

.venv패키지 버전 0.x

서로 다른 버전을 독립적으로 사용 가능

만약 모든 프로젝트가 같은 Python 패키지 설치 공간을 공유한다면, A 프로젝트에서 패키지를 업데이트했을 때 B 프로젝트가 제대로 작동하지 않을 수도 있어.

가상환경을 사용하면 각 프로젝트마다 독립적인 패키지 설치 공간을 가질 수 있어.

uv 프로젝트는 일반적으로 .venv라는 폴더에 이 환경을 만들어 줘.

LangChain 프로젝트 생성하기

이제 우리가 앞으로 학습할 프로젝트를 만들어 보자.

프로젝트 이름은 langchain-study로 정할게.

4-1. 프로젝트 생성 명령어

터미널에서 작업할 상위 폴더로 이동한 다음 다음 명령어를 실행해.

터미널
uv init --no-package --python 3.11 langchain-study

이 명령어에는 중요한 부분이 네 가지 있어.

부분의미
uv init새로운 Python 프로젝트 초기화
--no-package패키지 빌드 구조 없이 간단한 앱 프로젝트 생성
--python 3.11프로젝트의 Python 기준 버전 지정
langchain-study새로 만들 프로젝트 폴더 이름

왜 --no-package를 사용할까?

최신 uv는 일반적으로 uv init 실행 시 src/ 디렉터리를 사용하는 패키지형 구조를 생성해.

uv 0.12부터 새 애플리케이션의 기본 구조에 빌드 시스템과 src/가 포함돼. 이전 버전에서는 기본 구조가 다르게 보일 수 있어. 이번 강의처럼 --no-package를 명시하면 main.py를 직접 실행하는 간단한 구조로 시작할 수 있어. 프로젝트 생성 문서 ↗

하지만 우리는 당분간 main.py 파일을 직접 실행하면서 공부할 거라서 더 단순한 구조를 선택하는 거야. 이 방식 역시 공식적으로 지원돼. 프로젝트 생성 ↗

05

LangChain 패키지 설치하기

이제 본격적으로 LangChain을 설치할 차례야.

5-1. 어떤 패키지를 설치해야 할까?

이번 과정에서는 다음 3개 패키지를 사용하자.

패키지역할
langchainLangChain 핵심 기능과 에이전트 API
langchain-openaiOpenAI 모델 연동
python-dotenv.env 파일의 환경변수 불러오기

LangChain은 모델 공급자별 연동 패키지를 별도로 제공해. OpenAI를 사용하려면 langchain-openai를 설치하는 것이 공식적인 방법이야. LangChain 설치 ↗

5-2. 패키지 설치 명령어

프로젝트 폴더 안에서 실행해.

터미널
uv add langchain langchain-openai python-dotenv

uv add는 패키지를 설치하면서 프로젝트의 의존성 목록에도 등록하는 명령어야.

세 패키지를 한 번에 설치하도록 작성한 거야.

설치하는 동안 Resolved, Prepared, Installed 같은 메시지가 나타날 수 있어.

  • Resolved: 필요한 패키지와 호환 버전을 결정했어.
  • Prepared: 패키지를 다운로드하거나 설치 준비를 했어.
  • Installed: 패키지를 가상환경에 설치했어.

설치 시에는 하위 의존성 패키지도 함께 설치되기 때문에 우리가 지정한 3개보다 많은 패키지가 표시되는 것이 정상이야.

5-3. 가상환경이 자동으로 생성됐을까?

uv add를 실행하면 uv가 필요한 경우 .venv 폴더를 생성해.

따라서 이번 방식에서는 따로 python -m venv를 실행할 필요가 없어.

이제 프로젝트 구조는 다음과 비슷해져.

예상 결과 / 흐름
langchain-study/├── .venv/├── .python-version├── .gitignore├── README.md├── main.py├── pyproject.toml└── uv.lock

.venv와 uv.lock은 프로젝트 실행 또는 의존성 관리 과정에서 생성돼. 프로젝트 가이드 ↗

06

가상환경을 활성화해야 할까?

여기가 uv를 처음 배우는 사람이 가장 헷갈리는 부분이야.

기존 Python 개발에서는 가상환경을 활성화한 뒤 Python 프로그램을 실행하는 방법을 자주 사용했어.

예를 들어 Windows에서는 다음과 같은 명령어를 사용해.

PowerShell
.venv\Scripts\Activate.ps1

macOS나 Linux에서는 다음과 같이 사용하고.

터미널
source .venv/bin/activate

하지만 uv를 이용한 프로젝트 실행에서는 가상환경을 매번 수동으로 활성화할 필요가 없어.

터미널
uv run python main.py

이 명령어를 실행하면 uv가 프로젝트 가상환경을 사용해 Python 프로그램을 실행해 줘.

우리는 앞으로 이 방식을 기본으로 사용할 거야.

터미널
uv run python 파일이름.py

추가로 현재 uv가 어떤 Python을 사용하는지 확인할 수 있어.

터미널
uv run python -c "import sys; print(sys.executable)"

여기서 -c는 뒤에 작성한 Python 코드를 직접 실행한다는 뜻이야.

출력된 경로에 프로젝트의 .venv가 포함되어 있다면 정상적으로 가상환경을 사용하고 있는 거야.

sys는 Python에서 기본으로 제공하는 모듈이야.

현재 실행 중인 Python 버전이나 실행 경로 같은 정보를 확인할 수 있어.

② 설치된 패키지 버전을 확인하는 함수

Python
from importlib.metadata import version

importlib.metadata도 Python의 표준 라이브러리야.

version() 함수를 사용하면 설치된 패키지의 버전을 확인할 수 있어.

예를 들어:

Python
version("langchain")

설치되어 있는 LangChain 버전을 문자열로 반환해.

③ LangChain의 OpenAI 클래스 가져오기

Python
from langchain_openai import ChatOpenAI

이 코드는 langchain-openai 패키지의 ChatOpenAI 클래스를 불러와.

여기서는 실제 모델 객체를 생성하거나 API 요청을 보내지 않기 때문에 API 키가 필요 없어.

④ Python 버전 출력

Python
print("Python:", sys.version.split()[0])

조금 복잡해 보이지만 순서대로 보면 쉬워.

  • sys.version: Python 버전과 빌드 정보가 들어 있는 문자열
  • .split(): 공백을 기준으로 문자열을 분리
  • [0]: 분리된 문자열의 첫 번째 값 선택
  • print(): 결과 출력

따라서 3.11.x와 같은 Python 버전 번호가 출력돼.

⑤ 패키지 버전 출력

Python
print("LangChain:", version("langchain"))

현재 설치된 LangChain 버전이 출력돼.

version("langchain-openai")도 같은 방식으로 작동해.

⑥ 프로그램 실행 조건

Python
if __name__ == "__main__":    main()

이 코드는 해당 Python 파일을 직접 실행했을 때 main() 함수를 호출한다는 의미야.

다른 파일에서 모듈로 가져오는 경우에는 이 조건이 일반적으로 성립하지 않아.

7-3. 프로그램 실행

터미널에서 다음 명령어를 실행해.

터미널
uv run python check_env.py

예상되는 출력 형식은 다음과 같아.

예상 결과 / 흐름
=== 개발 환경 확인 ===Python: 3.11.xLangChain: 설치된 버전LangChain OpenAI: 설치된 버전ChatOpenAI 가져오기 성공!개발 환경 준비 완료!

실제로는 3.11.x 대신 정확한 Python 패치 버전이, 설치된 버전 대신 각각의 패키지 버전 번호가 출력될 거야.

이 결과가 나타난다면 LangChain 개발 환경 구축에 성공한 거야.

08

uv의 중요한 파일 이해하기

실무에서도 자주 사용하는 부분이라 꼭 알아두면 좋아.

8-1. pyproject.toml이란?

pyproject.toml은 Python 프로젝트를 정의하는 설정 파일이야.

우리가 uv add로 패키지를 추가하면 이 파일에 의존성 정보가 자동으로 기록돼.

실제 파일에는 대략 다음과 같은 정보가 들어 있어.

항목의미
name프로젝트 이름
version프로젝트 버전
requires-python요구하는 Python 버전 범위
dependencies프로젝트가 사용하는 패키지 목록

예를 들어 dependencies에는 LangChain과 OpenAI 연동 패키지 등이 들어가게 돼. uv는 패키지 추가 시 결정한 버전 조건도 자동으로 기록해 주므로 처음에는 직접 수정할 필요 없어.

8-2. uv.lock이란?

uv.lock은 프로젝트에서 사용할 의존성의 구체적인 버전과 해결 결과를 기록하는 파일이야.

비교해 보자.

파일역할
pyproject.toml어떤 패키지가 필요한지 선언
uv.lock어떤 버전 조합으로 설치할지 기록

개발자 A와 B가 같은 프로젝트를 실행할 때 uv.lock을 함께 사용하면 의존성 버전을 일관되게 맞추는 데 도움이 돼.

이 파일은 보통 직접 수정하지 않고 uv가 관리하도록 두는 것이 좋아. 잠금과 동기화 ↗

8-3. 프로젝트를 다른 컴퓨터에서 실행한다면?

프로젝트를 GitHub 등에서 가져왔다고 생각해 보자.

그때는 프로젝트 폴더 안에서 다음 명령어를 사용할 수 있어.

터미널
uv sync

uv sync는 선언된 의존성과 잠금 파일을 바탕으로 프로젝트의 가상환경을 동기화해.

Git에 포함할 파일과 제외할 파일

파일Git에 포함?
main.py포함
check_env.py포함
pyproject.toml포함
uv.lock포함
.python-version포함
.venv/제외
.env제외

.env 파일에는 다음 강의부터 API 키를 저장할 수 있으므로 Git에 올라가지 않도록 주의해야 해.

.gitignore 파일에 다음 항목이 있는지 확인해 봐.

.gitignore
.venv/.env

기존에 .venv/가 들어 있다면 중복 추가할 필요는 없어. 또한 .gitignore는 이미 Git에 추적되고 있는 비밀 파일을 자동으로 보호하지는 않으므로, API 키가 담긴 파일은 처음부터 Git에 추가하지 않는 것이 중요해.

09

uv 핵심 명령어 정리

처음부터 명령어를 전부 외울 필요는 없어.

아래 8개 정도를 우선 익히면 충분해.

명령어기능
uv --versionuv 버전 확인
uv python install 3.11Python 3.11 설치
uv init --no-package간단한 프로젝트 초기화
uv add 패키지명패키지 추가
uv remove 패키지명패키지 제거
uv run python main.py프로젝트 환경에서 실행
uv sync의존성 동기화
uv tree의존성 트리 확인

여기서 uv lock도 알아두면 좋아. 패키지들의 의존성 해결 결과를 uv.lock에 기록하거나 갱신하는 명령어야.

다만 일반적인 uv add와 uv run 과정에서도 잠금 파일이 자동으로 관리되기 때문에 매번 수동으로 실행할 필요는 없어.

간단한 연습

다음 명령어를 실행해 봐.

터미널
uv tree

프로젝트에서 어떤 패키지를 사용하고, 각각의 패키지가 다른 어떤 패키지를 필요로 하는지 계층 구조로 확인할 수 있어.

또 하나 기억하자.

uv 프로젝트에서는 가능하면 pip install 패키지명보다는 uv add 패키지명을 사용하자.

uv add는 패키지를 설치하는 것뿐만 아니라 프로젝트 설정과 잠금 파일도 함께 관리하기 때문이야.

10

자주 발생하는 오류와 해결 방법

오류 ① uv 명령어를 찾을 수 없음

예상 결과 / 흐름
uv: command not found

Windows에서는 다음과 비슷하게 나타날 수 있어.

예상 결과 / 흐름
'uv' is not recognized...

원인: uv가 설치되지 않았거나, 설치 경로가 PATH에 반영되지 않았을 수 있어.

해결: 터미널을 완전히 닫고 다시 열어 uv --version을 실행해. 여전히 안 된다면 설치 과정에서 PATH 설정 안내가 있었는지 확인하고 공식 설치 방법을 다시 점검해.

오류 ② ModuleNotFoundError

예상 결과 / 흐름
ModuleNotFoundError: No module named 'langchain_openai'

원인: 패키지가 설치되지 않았거나, 코드 실행 시 다른 Python 환경을 사용하고 있을 수 있어.

프로젝트 폴더에서 다음 명령어를 실행해.

터미널
uv add langchain-openaiuv run python check_env.py

python check_env.py 대신 uv run python check_env.py로 실행하는 것이 중요해.

오류 ③ pyproject.toml을 찾을 수 없음

원인: 현재 터미널이 프로젝트 폴더 밖에 있을 수 있어.

다음 명령어로 이동해.

터미널
cd langchain-study

현재 위치에서 pyproject.toml이 보이는지 확인한 다음 다시 실행해.

오류 ④ Python 버전 또는 패키지 호환성 문제

다음과 같은 메시지가 발생할 수 있어.

예상 결과 / 흐름
No solution found when resolving dependencies

원인은 다양하지만 Python 버전 요구사항이나 패키지 간 버전 충돌이 흔한 이유야.

우선 다음 명령어로 버전을 확인해.

터미널
uv run python --version

그리고 pyproject.toml의 requires-python 값과 오류 메시지에 표시된 패키지 요구사항을 확인해.

이번 실습에서는 프로젝트를 Python 3.11 기준으로 생성해야 해.

오류 ⑤ VS Code에서는 import 오류가 표시되지만 터미널에서는 실행됨

VS Code가 프로젝트의 가상환경이 아닌 다른 Python을 선택했을 수 있어.

VS Code에서 Ctrl+Shift+P(macOS는 Cmd+Shift+P)를 누른 다음 Python: Select Interpreter를 찾아 실행해.

아래 경로의 Python을 선택하면 돼.

Windows

예상 결과 / 흐름
.venv\Scripts\python.exe

macOS / Linux

예상 결과 / 흐름
.venv/bin/python

오류 ⑥ 패키지 다운로드가 실패함

네트워크 오류나 인증서 오류가 나타날 수 있어.

우선 인터넷 연결과 프록시·방화벽 설정을 확인하고 다음 명령어로 다시 시도해.

터미널
uv sync

회사 네트워크에서 인증서 오류가 발생했다면 인증서 설정을 확인해야 해. 보안 검증을 무조건 끄는 방식은 권장하지 않아.
