코드는 복사하거나 파일 저장 버튼으로 내려받아 터미널에서 실행해. 실제 모델을 호출하는 예제는 API 키와 인터넷 연결이 필요하고 사용 요금이 발생할 수 있어.

드디어 우리가 만든 Python 프로그램에서 실제 AI 모델을 호출하는 단계야.

이번 강의에서는 다음 네 가지를 확실하게 이해하는 것이 목표야.

  • ChatOpenAI — OpenAI의 채팅 모델을 사용하는 객체
  • invoke() — 모델에 입력을 전달하고 응답을 받아오는 메서드

  • response.content — 응답 메시지의 내용에 접근하는 방법

이번 강의가 끝나면 이런 프로그램을 직접 실행할 수 있어.

01

LLM 호출은 어떻게 작동할까?

1-1. 먼저 전체 구조 이해하기

지금까지 우리는 uv, Python 프로젝트, .env, API 키를 준비했어.

이제 그 도구들이 하나로 연결돼.

첫 LLM 호출 과정

① 사용자 질문

"Python 함수가 뭐야?"

② Python + LangChain

model.invoke(질문)

③ OpenAI API

API 키 인증 후 모델 처리

④ AIMessage 반환

응답 내용 + 토큰 사용량 등

⑤ 사용자에게 출력

print(response.content)

중요한 점이 있어.

우리는 GPT 모델을 내 컴퓨터에 설치하는 게 아니야. 인터넷을 통해 OpenAI 서버의 모델에 요청을 보내고, 그 결과를 받아오는 거야.

LangChain은 이 과정을 편리하게 다룰 수 있는 인터페이스를 제공해. 공식 문서 ↗

1-2. API 요청이란?

예를 들어 다음 코드를 실행한다고 생각해 보자.

Python
response = model.invoke("안녕하세요!")

내부에서는 대략 다음 일이 일어나.

  1. LangChain이 입력을 모델 요청 형식으로 변환해.
  2. OpenAI SDK를 통해 API 요청을 전송해.
  3. OpenAI 서버에서 API 키와 사용 권한 등을 확인해.
  4. 지정된 모델이 입력을 처리해.
  5. 응답이 반환되면 LangChain이 이를 AIMessage 객체로 제공해.

개발자인 우리는 이 과정을 전부 직접 구현하지 않아도 돼.

04

코드 한 줄씩 자세히 해설하기

이제 코드를 여러 부분으로 나눠서 살펴보자.

4-1. 필요한 모듈 가져오기

Python
import osfrom pathlib import Path from dotenv import load_dotenvfrom langchain_openai import ChatOpenAI
코드의미
import os환경변수를 읽기 위해 Python 기본 모듈 사용
from pathlib import Path파일 경로를 다루는 클래스 가져오기
from dotenv import load_dotenv.env 파일을 읽는 함수 가져오기
from langchain_openai import ChatOpenAIOpenAI 채팅 모델 클래스 가져오기

여기서 ChatOpenAI가 이번 강의의 주인공이야.

4-2. 환경변수 불러오기

Python
env_path = Path(__file__).resolve().parent / ".env"load_dotenv(dotenv_path=env_path)

첫 번째 줄은 현재 Python 파일과 같은 폴더에 있는 .env 파일의 경로를 만들어.

두 번째 줄은 해당 파일을 읽어서 현재 Python 프로세스의 환경변수에 설정해.

이번 코드는 이전 강의와 동일한 방식이야.

4-3. API 키 존재 여부 확인

Python
api_key = os.getenv("OPENAI_API_KEY")

os.getenv()는 환경변수를 읽는 함수야.

.env 파일의 OPENAI_API_KEY 값이 api_key에 들어가.

다음 코드도 보자.

Python
if not api_key or api_key == "put_your_real_api_key_here":    raise RuntimeError("OPENAI_API_KEY를 .env에 설정해 주세요.")

if 조건이 참이면 raise를 통해 오류를 발생시키고 프로그램 실행을 중단해.

RuntimeError는 Python의 기본 예외 클래스 중 하나야.

이렇게 하는 이유는 API 키가 없는 상태에서 불필요한 모델 요청을 시도하지 않기 위해서야.

단, 이 검사는 키가 존재하는지만 확인해. 실제로 인증에 성공하는지는 API 호출 시 확인돼.

4-4. ChatOpenAI 이해하기

Python
model = ChatOpenAI(model="gpt-5.4-mini")

이 한 줄을 정확히 이해해 보자.

① ChatOpenAI

LangChain에서 OpenAI의 채팅 모델을 사용하기 위한 클래스야.

Python에서 클래스는 객체를 만들기 위한 설계도라고 생각하면 돼.

② ChatOpenAI(...)

클래스를 사용해 실제 객체를 생성하는 부분이야.

객체에는 모델을 호출하는 invoke() 같은 메서드가 있어.

③ model="gpt-5.4-mini"

사용할 OpenAI 모델의 이름을 지정하는 인자야.

왼쪽 model은 매개변수 이름이고, 오른쪽 "gpt-5.4-mini"는 실제 전달되는 문자열 값이야.

④ model = ...

생성한 객체를 model이라는 Python 변수에 저장하는 부분이야.

model은 우리가 정한 변수 이름이므로 llm이나 chat_model이라고 작성해도 돼.

중요한 차이

ChatOpenAI()는 모델과 통신할 수 있는 객체를 준비하는 단계야.

이 코드만으로는 일반적으로 실제 답변을 생성하는 API 요청이 발생하지 않아.

실제 모델 호출은 다음에 배울 invoke()에서 일어나.

4-5. invoke() 이해하기

Python
response = model.invoke(question)

이번 강의에서 가장 중요하게 기억해야 할 코드야.

각 부분의 의미는 다음과 같아.

코드의미
model앞서 만든 ChatOpenAI 객체
.invoke()입력을 전달하고 실행 결과를 받는 메서드
question모델에 전달할 질문 문자열
response =반환된 값을 Python 변수에 저장

예를 들어 일반 Python 함수에서는 다음처럼 작성할 수 있지.

Python
def greet(name):    return f"안녕하세요, {name}님!" result = greet("철수") print(result)

함수 greet()를 실행한 결과를 result에 저장했어.

invoke()도 입력을 전달하고 결과를 받는다는 점에서는 비슷해.

하지만 차이점이 있어.

greet()는 내 컴퓨터에서 작성된 코드를 실행하지만, model.invoke()는 외부 API와 통신해서 실제 모델의 결과를 받아오는 작업이야.

또한 invoke()는 동기 방식이므로 요청이 완료되거나 오류가 발생할 때까지 해당 호출이 끝나기를 기다려.

비동기 방식인 ainvoke()는 2-8강에서 배울 거야.

4-6. response.content 이해하기

Python
print(response.content)

response에는 AI 모델의 응답 객체가 저장되어 있어.

여기서 .content는 그 메시지의 내용을 가져오는 속성이야.

우리가 지금처럼 일반 텍스트 질문을 보내고 텍스트 응답을 받는 경우, 보통 .content에 AI가 생성한 문자열이 담겨 있어.

print()로 출력하면 터미널에서 읽을 수 있지.

이제 왜 응답 객체에서 .content를 꺼내는지 알아보자.

05

AIMessage란 무엇일까?

우리가 작성한 코드는 다음과 같았지.

Python
response = model.invoke(question)

여기서 response에 들어가는 것은 단순한 문자열이 아니야.

LangChain은 일반적인 채팅 모델의 응답을 AIMessage라는 객체로 반환해. 공식 문서 ↗

5-1. 문자열과 객체의 차이

예를 들어 일반 문자열은 다음과 같아.

Python
answer = "안녕하세요!"

하지만 실제 모델 응답에는 답변뿐만 아니라 추가 정보도 포함될 수 있어.

AIMessage 객체

content

AI가 생성한 답변 내용

usage_metadata

입력·출력 토큰 사용량

response_metadata

모델 이름, 종료 사유 등의 정보

id

응답과 실행을 식별하는 정보

즉, AIMessage는 AI의 답변과 관련된 정보를 담는 객체라고 이해하면 돼.

5-2. response와 response.content의 차이

다음 두 코드를 비교해 보자.

Python
print(response)
Python
print(response.content)

첫 번째는 응답 객체의 표현을 출력해. 답변 내용 외에 메타데이터 등이 함께 표시될 수 있어.

두 번째는 응답 객체에서 content 속성만 가져와 출력해.

이번처럼 일반적인 텍스트 응답을 받는 경우에는 주로 두 번째 방식을 사용하면 돼.

다만 앞으로 도구 호출이나 멀티모달 기능을 학습하면 content가 문자열 대신 여러 콘텐츠 블록을 담은 리스트일 수도 있어. 지금은 일반 텍스트 응답만 생각하면 충분해.

실습 ② AIMessage 객체 분석하기

이번에는 실제로 어떤 형태의 객체가 반환되는지 확인해 보자.

6-1. 파일 작성

새로운 파일 inspect_response.py를 만들어.

inspect_response.py
파일 저장 ↓
import osfrom pathlib import Path from dotenv import load_dotenvfrom langchain_openai import ChatOpenAIfrom langchain_core.messages import AIMessage # .env 불러오기env_path = Path(__file__).resolve().parent / ".env"load_dotenv(dotenv_path=env_path) if not os.getenv("OPENAI_API_KEY"):    raise RuntimeError("OPENAI_API_KEY를 설정해 주세요.") # 모델 생성model = ChatOpenAI(model="gpt-5.4-mini") # 실제 API 호출response = model.invoke("Python이 무엇인지 한 문장으로 설명해 줘.") # 응답 정보 확인print("=== 응답 분석 ===") print("객체 타입:", type(response).__name__)print("AIMessage인가?", isinstance(response, AIMessage)) print("\n답변 내용:")print(response.content) print("\n토큰 사용량:")print(response.usage_metadata) print("\n모델 정보:")print(response.response_metadata.get("model_name", "정보 없음"))

6-2. 새롭게 등장한 문법

① AIMessage 가져오기

Python
from langchain_core.messages import AIMessage

langchain_core.messages는 LangChain에서 메시지와 관련된 자료형을 제공하는 모듈이야.

여기서 AIMessage 클래스를 가져오는 거야.

② type()으로 객체 타입 확인

Python
print(type(response).__name__)

type()은 Python 객체의 자료형을 확인하는 함수야.

.__name__은 해당 자료형의 이름을 문자열로 가져와.

따라서 AIMessage라고 출력되는 것을 확인할 수 있어.

③ isinstance() 이해하기

Python
print(isinstance(response, AIMessage))

isinstance()는 객체가 특정 클래스의 인스턴스인지 확인하는 Python 기본 함수야.

조건에 맞으면 True, 아니면 False를 반환해.

여기서는 response가 AIMessage 객체인지 확인하는 거야.

④ 사용량 확인하기

Python
print(response.usage_metadata)

이 코드는 입력 토큰과 출력 토큰 등의 사용량 정보를 보여줘.

⑤ 모델 정보 확인하기

Python
print(response.response_metadata.get("model_name", "정보 없음"))

response_metadata에 있는 모델 이름을 가져오는 코드야.

.get()은 딕셔너리에서 특정 키의 값을 읽을 때 사용하는 메서드야.

해당 키가 없다면 "정보 없음"이라는 기본값을 사용해.

7-1. 토큰(Token)이란?

LLM은 텍스트를 처리할 때 토큰이라는 단위를 사용해.

토큰은 단어나 문자와 완전히 일치하지 않아. 영어, 한국어, 공백, 문장부호 등이 모델의 토크나이저에 따라 다르게 나뉠 수 있어.

예를 들어:

예상 결과 / 흐름
입력:"Python에서 함수란 무엇인가요?" ↓ 토큰화 LLM이 처리하는 토큰들의 시퀀스

API 비용은 일반적으로 모델별 입력 토큰과 출력 토큰 사용량을 기준으로 계산돼.

7-2. 입력 토큰과 출력 토큰

입력 토큰

모델에 전달한 질문, 지시문 등의 토큰

출력 토큰

모델이 생성한 응답 등에 사용된 토큰

모델에 따라 내부 추론 토큰도 출력 토큰 사용량에 포함될 수 있어.

자주 발생하는 오류와 해결 방법

이번 강의에서는 처음으로 실제 API를 호출하기 때문에 새로운 오류가 발생할 수 있어.

오류주요 원인해결 방법
ModuleNotFoundError패키지 누락 또는 다른 Python 환경 사용uv add와 uv run 확인
AuthenticationError / 401API 키가 잘못되었거나 폐기됨올바른 프로젝트의 키 확인
RateLimitError / 429호출 속도 제한, 크레딧 또는 사용 한도 문제세부 오류 코드 확인
NotFoundError / 404모델 또는 리소스가 존재하지 않음모델 ID 확인
PermissionDeniedError / 403사용 권한 부족프로젝트 및 모델 권한 확인
APIConnectionError네트워크 연결 문제인터넷·방화벽·프록시 확인

특히 429 오류는 두 가지를 구분해야 해.

요청을 너무 빠르게 보내 발생한 속도 제한이라면 요청 간격을 조정할 수 있어. 반면 크레딧 부족이나 예산 한도 초과라면 반복 호출한다고 해결되지 않아. 공식 문서 ↗

.env를 수정해도 API 키가 변경되지 않을 때

이전 강의에서 배운 load_dotenv()는 기본적으로 이미 존재하는 환경변수를 덮어쓰지 않아.

따라서 터미널에 예전 API 키가 설정되어 있다면 .env 파일의 새 키 대신 기존 키가 사용될 수 있어.

기존 환경변수를 확인하고 정리해야 할 수 있으므로, 단순히 API 요청을 반복하기보다는 설정을 먼저 점검하는 것이 좋아.

또한 오류 로그를 질문할 때는 실제 API 키가 포함되지 않도록 확인해야 해.
